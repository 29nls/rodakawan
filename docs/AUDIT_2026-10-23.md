## 3. Keputusan teknis P0

1. **Identitas login dihapus, konten keselamatan dipertahankan.** `profiles.id`
   tidak lagi memiliki FK ke `auth.users`; trigger menjaga integritas arah
   sebaliknya. Profil akun dihapus, konten yang wajib dipertahankan dialihkan ke
   tombstone bersama `00000000-0000-4000-8000-000000000001`.
2. **Satu orkestrator server.** Edge Function `delete-account` memverifikasi JWT
   sendiri, memakai service role hanya di server, dan menjalankan Storage → DB →
   Auth. Klien tidak mengirim `userId`.
3. **Storage sebelum Auth.** Logo klub yang masih dipakai disalin ke path baru
   dan referensinya diperbarui; objek pribadi/yatim dihapus. Kegagalan di sini
   menghentikan proses sebelum Auth dihapus.
4. **Retry berbasis job.** `account_deletion_jobs` menyimpan langkah terakhir
   yang selesai; job `completed` idempoten; kegagalan parsial dapat diulang.
5. **Jalur web terpisah.** Halaman statis memakai Supabase Auth REST (login
   password) lalu Edge Function yang sama. Tidak ada SDK/CDN, token disimpan di
   memori, dan pesan login dibuat generik agar tidak membocorkan email terdaftar.
